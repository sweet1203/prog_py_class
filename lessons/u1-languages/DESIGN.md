**50분 흐름(참고)** — 시작(8분) 이야기·파이썬 특징·핵심질문/목표/계획 → 01(9분) 프로그래밍 과정·소프트웨어·용어 카드·퀴즈 → 02(9분) 하드웨어·소프트웨어 계층, 실행 과정 SVG 단계, 퀴즈 → 03(14분) 세 기준·저급/고급·컴파일/인터프리트 탭·절차/객체 분류 게임·개발 분야, 퀴즈 → 04(6분) 수행 활동 메모·점검 → 마무리(4분) 퀴즈·질문폼.

**질문폼 근거(prog-u1-languages)** — 1번 ← 01 프로그래밍 과정·02 실행 과정, 2번 ← 03 세 기준·컴파일/인터프리트, 3번 ← 04 분야·언어 선택 메모(`devFieldPick`·`progName`·`progDesc`·`langChoose`·`langReason`). 근거 활동이 03~04에 몰려 있으므로 수업 후반을 확보.

**줄인 것·접은 것**
- 21쪽 「소프트웨어 기술자 직종 및 직무」 표(16직종)는 진로 참고 자료라 화면에 넣지 않음(설계안의 「optional」 반영).
- 15쪽 그림Ⅰ-1(다양한 프로그램 활용 사진), 18쪽 그림Ⅰ-5(자연어/프로그래밍 언어/기계어), 19쪽 저급 언어 측면 그림, 20쪽 그림Ⅰ-6(자전거 삽화)은 이미지 대신 글·비유·게임으로 풀어 씀.
- 23쪽 「핵심 정리」 개념도는 빈칸으로 만들지 않고 key3로 풀어 씀(공개 저장소). 23쪽 성취도 평가 A~E 척도표는 04의 자기 점검 `chips`로 대체.
- 보기 코드(`<pre class="code">`)는 이 차시에 쓰지 않음(개념 차시). 다만 지침대로 `.code` 스타일은 lesson.css에 넣어 둠(이후 차시 재사용).

**확인할 점**
- 18쪽 표Ⅰ-1 제목은 「저급 언어/고급 언어」가 아니라 「기계와 사람 중심 분류」임. 화면에서도 기준 이름(기계와 사람 중심)과 하위 분류(저급·고급)를 구분해 표기.
- 16·17쪽: 「프로그램은 대체로 응용 소프트웨어에 속한다」를 그대로 반영. 프로그램=시스템 소프트웨어로 오해하지 않도록 01 카드에 명시.
- 19쪽 컴파일 설명의 「프로그램의 개발 단계에서 코드를 조금씩 추가하면서 빠르게 테스트」는 교과서 편집상 인터프리트 쪽 특징으로 배치되어 있어, 탭에서도 인터프리트의 장점으로 둠(대화식·빠른 테스트).
- 교과서는 `어셈블리어→어셈블러`, `컴파일→컴파일러`, `인터프리트→인터프리터`로 번역 프로그램 이름을 구분. 화면에서도 방식(컴파일/인터프리트)과 프로그램(컴파일러/인터프리터)을 구분해 표기.
- SVG 실행 흐름의 박스 배치(입력/출력 위, CPU·RAM·보조기억 세로)와 「2+3=5」는 그림Ⅰ-4를 알아보기 쉽게 재배치·단순화한 것(결괏값은 교과서 설명대로 「주기억 장치를 거쳐 출력 장치로」를 캡션에 명시).
- 설계안 「공통 체크」의 교과서 쪽 표기(참고용), 차시 번호·날짜·주소 미기재 준수. 질문폼 링크는 `{{FORM_URL}}` 자리표시(빌드 치환). `course.json`·`forms`는 건드리지 않음 → 총괄이 form(prog-u1-languages) 등록 후 build/check.

**지어낸 것(예시 표시)**
- 02 실행 흐름 SVG의 박스 위치·화살표는 그림Ⅰ-4를 재배치한 것. 실제 기기 내부 구조가 아니라 흐름을 보여 주는 도식.
- 03 분류 게임 8장 중 자전거·언어 예는 교과서(표Ⅰ-2·그림Ⅰ-6) 기반, 「문제 해결 과정을 순서대로…」 등 특징 문장은 교과서 표현을 풀어 쓴 것.
- 04 입력칸 안내 문구의 예(「영어 단어 암기 게임」, 「Python」)는 보기용.
- 0 시작 파이썬 특징 카드 4장은 18쪽 「파이썬의 발전」 문단을 네 갈래로 나눠 정리한 것(새 사실 추가 없음).
