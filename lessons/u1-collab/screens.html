01

공유·협업과 버전 관리

교과서 54·56쪽 · 왜 버전 관리가 필요할까

쉽게 말하면개발을 하다 보면 코드를 고쳤다 되돌렸다 하고, 여럿이 같은 파일을 동시에 고치기도 해요. 이걸 안전하게 관리해 주는 것이 버전 관리예요. 깃은 버전을 관리하는 도구, 깃허브는 그 코드를 인터넷에 올려 함께 쓰는 공간이라고 생각하면 돼요.

👥 왜 협업에는 버전 관리가 필요할까? (54·56쪽)

팀 프로젝트에서는 개발자마다 역할을 나눠 코드를 쓰고, 그것을 모아 하나로 합쳐야(병합) 해요. 또 개발 중에는 코드를 고치고 되돌리는 일이 자주 생기죠. 이런 일을 체계적으로 돕는 것이 버전 관리예요.

😵 버전 관리가 없으면코드_최종.py, 코드_최종2.py, 진짜최종.py … 파일이 쌓이고, 누가 무엇을 바꿨는지 알기 어려워요.
→
😊 버전 관리가 있으면변경 내역을 추적하고, 이전 상태로 되돌리고, 동시 수정으로 생긴 충돌도 합쳐서 해결할 수 있어요.

🔧 깃(git) vs 깃허브(GitHub) (54·56쪽)

비슷해 보이지만 하는 일이 달라요. 둘은 짝을 이뤄 함께 쓰여요.

💾 깃(git) 소스 코드를 내 컴퓨터(로컬)에 독립적으로 저장해 버전을 관리하는 분산 버전 관리 시스템이에요. 변경 사항을 추적하고, 여럿이 동시에 작업하는 병렬 개발과 충돌 병합을 지원해요. 혼자 하는 프로젝트도 버전을 정리해 포트폴리오로 쓸 수 있어요.
☁️ 깃허브(GitHub) 깃으로 관리하는 코드를 클라우드에 저장하도록 돕는 웹 기반 호스팅 서비스예요. 여러 개발자가 협업하고, 프로젝트를 오픈 소스로 공개하거나 남의 오픈 소스를 활용할 수 있어요. 가입은 깃허브 사이트(github.com)에서 해요.

브랜치(branch) · 기존 코드에 영향을 주지 않고 새 기능을 추가하거나 버그를 수정하도록 만든 독립적인 작업 공간이에요. 각자 브랜치에서 작업한 뒤 병합(merge)해 하나로 통합해요.

⬇️ 깃 설치와 환경 설정 (56쪽)

깃은 깃 사이트(git-scm.com)에서 운영체제에 맞는 설치 파일을 내려받아 설치해요. 설치한 뒤에는 깃허브에 등록한 이름과 이메일을 깃에도 등록해 둬요.

git config --global user.name '계정 아이디'   # 이름 등록
git config --global user.email '이메일 주소'  # 이메일 등록
git config --list                       # 등록이 잘 됐는지 확인

🎬 깃 설치 영상·QR과 설치 화면은 「선생님 자료」로 함께 봐요. 설치 방법은 운영체제에 따라 조금씩 달라요.

02

깃으로 버전 관리하기

교과서 57~58쪽 · 버전 관리 과정과 주요 명령어

쉽게 말하면내 코드를 깃허브에 올리는 길은 작업 폴더 → 스테이지 → 로컬 저장소 → 원격 저장소 네 칸을 거쳐요. 칸을 넘길 때마다 쓰는 명령이 add · commit · push이고, 반대로 가져올 때는 pull이에요.

🔄 깃을 활용한 버전 관리 과정 (57쪽 그림Ⅰ-30)

버튼을 눌러 단계를 하나씩 밝혀 봐요. 어떤 명령이 코드를 어느 칸으로 옮기는지 살펴봐요.

스테이지(Staging Area) · 커밋하기 전에 변경된 파일을 준비해 두는 임시 저장 공간이에요.

⌨️ 코드를 처음 올리는 명령 흐름 (57쪽)

실제 명령은 아래와 같아요. 여기서는 읽어 보기만 해요(직접 실행하지 않아요).

cd MyProject                      # 프로젝트 폴더로 이동
git init                          # 이 폴더를 깃 저장소로 초기화
git remote add origin <원격 저장소 URL>  # 원격 저장소와 연결
git add .                         # 변경된 모든 파일을 스테이지에 올리기
git commit -m 'first project'      # 로컬 저장소에 기록하기
git push origin main              # 원격 저장소에 전송하기
프로그래밍 소스 파일이 든 폴더를 깃 저장소로 초기화해요.
깃허브에서 만든 원격 저장소와 연결해요.
작업한 파일을 스테이지에 올려요.
스테이지의 내용을 커밋 메시지와 함께 기록해요.
변경 사항을 원격 저장소에 추가로 전송해요.

🃏 깃 주요 명령어 매칭 (58쪽 표Ⅰ-6)

카드를 눌러 명령어가 하는 일과 예시를 확인해요. 무엇을 하는 명령인지 먼저 떠올려 본 뒤 뒤집으면 더 잘 외워져요.

03

깃허브와 협업

교과서 54~55·58쪽 · 저장소 만들기, 함께 개발하기

쉽게 말하면깃허브에 원격 저장소를 하나 만들면, 거기에 코드를 올려 두고 여럿이 함께 가져다 고치고 다시 올릴 수 있어요. 각자 브랜치에서 작업한 뒤 병합하면 충돌 없이 하나로 합쳐져요.

🗃️ 깃허브에서 원격 저장소 만들기 (54~55쪽)

깃허브 사이트(github.com)에 가입·로그인한 뒤, 아래 순서로 원격 저장소(Repository)를 만들어요.

화면에서 Create repository를 눌러 새 원격 저장소 폴더를 만들어요.
Owner(계정 아이디) 옆 빈칸에 저장소 폴더 이름을 입력해요.
공개 범위로 Public을 고르고, 맨 아래 Create repository 버튼을 눌러 완료해요.
만들어진 저장소의 URL을 확인해 두면, 로컬 저장소와 연결할 때 써요.

Public은 인터넷의 누구나 볼 수 있고, Private은 내가 지정한 사용자만 볼 수 있도록 설정해요.

🌿 브랜치로 나눠 짜고, 병합으로 합치기 (54쪽)

🌿 브랜치에서 작업기존 코드를 건드리지 않는 독립 공간에서 각자 새 기능·수정 작업을 해요.
🔀 병합(merge)각 브랜치의 작업을 하나로 합쳐 프로젝트를 통합해요. 토론으로 품질도 높여요.
🌍 오픈 소스프로젝트를 공개하거나 남의 오픈 소스를 활용해 개발에 참여할 수 있어요.

🛠️ 협업을 돕는 커뮤니케이션 도구 (58쪽 「정보」)

여러 명이 함께 개발할 때는 일정·역할·진행 상황을 명확히 공유해야 해요. 온라인 협업 도구를 쓰면 더 효율적이에요.

노션(notion)프로젝트 관리·문서 정리·데이터베이스를 통합해 업무를 관리하는 협업 도구예요.
지라(jira)이슈·프로젝트 추적 소프트웨어로, 업무를 시각화하고 유연한 관리를 지원해요.
슬랙(slack)채널 기반 메시징 플랫폼으로, 실시간 소통과 협업을 효과적으로 지원해요.

✍️ 협업 상황 메모

혼자 코드를 관리할 때와, 여럿이 함께 관리할 때를 떠올려 적어 봐요. 마지막 화면에서 다시 볼 수 있어요.

1️⃣ 내 원격 저장소 계획하기

2️⃣ 깃으로 올리는 순서 다시 떠올리기 (60쪽 활동)

아래 흐름을 보며, 내 저장소에 적용하면 어떤 명령을 차례로 쓸지 상상해 봐요.

05

마무리 · Ⅰ단원 4절 정리

핵심 문장 · 마무리 퀴즈 · 생각 정리 질문폼

깃(git)은 코드의 이력을 추적·수정·복원하는 분산 버전 관리 시스템이고, 깃허브(GitHub)는 여러 개발자가 코드를 관리·병합하며 협업하도록 돕는 공유·협업 환경(웹 호스팅 서비스)이다.
코드는 작업 폴더 → (add) 스테이지 → (commit) 로컬 저장소 → (push) 원격 저장소 순서로 올라가고, 원격 저장소의 변경 내용은 pull로 다시 가져온다. 각자 브랜치에서 작업한 뒤 병합(merge)해 하나로 통합한다.
Ⅰ단원 4절 정리 · 통합 개발 환경(IDE)은 에디터·컴파일러/인터프리터·디버거를 하나로 모은 개발 프로그램이다. 설치해 쓰는 로컬 IDE(VSCode·PyCharm 등)와 웹에서 쓰는 클라우드 IDE(Colab·Replit 등)가 있고, 공유·협업은 깃·깃허브로 한다.
