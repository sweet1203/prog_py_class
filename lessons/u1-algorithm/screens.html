3. 알고리즘 · 도입 (32~33쪽)

주어진 문제를 해결하려면 알고리즘의 기본 개념을 이해하는 것이 중요해요. 문제를 정확히 파악하고, 합리적이고 논리적인 사고로 문제 해결에 적합한 방법을 작성해야 하지요. 특히 순서도처럼 시각적인 표현 도구로 구조화하면, 알고리즘을 더 명확하고 체계적으로 정리할 수 있어요.

🧭 알고리즘은 일상 곳곳에 있어요 (33쪽)

우리는 선택을 하거나 문제를 풀어야 할 때 가장 합리적인 방법을 찾아가며 생활해요. 카드를 눌러 알고리즘이 무엇인지 느껴 봐요.

알고리즘이 「문제를 푸는 합리적인 순서·방법」이라는 느낌만 잡아 두세요. 자세한 조건과 표현은 01·02 화면에서 만나요.

01

알고리즘의 이해

교과서 33~35쪽 · 알고리즘의 정의·필요성·조건

쉽게 말하면알고리즘은 문제를 푸는 「가장 똑똑한 순서」예요. 요리로 치면 조리법(레시피), 프로그램으로 치면 코드를 짜기 전에 먼저 그리는 설계도랍니다. 알고리즘이 「계획」이라면 프로그램은 그 계획을 「실행」한 결과예요.

🧩 알고리즘이란? (33쪽 그림Ⅰ-12)

특정한 문제를 합리적으로 해결하기 위한 논리적인 절차 또는 방법을 알고리즘(algorithm)이라고 해요. 음식을 만드는 방법(조리법)에 비유할 수 있어요. 아래는 빵을 만드는 조리법을 알고리즘처럼 순서대로 적은 예예요.

1 반죽 뭉치기재료를 모아 반죽을 만들어요.
→
2 반죽 밀기반죽을 납작하게 밀어요.
→
3 재료 올리기반죽 위에 재료를 올려요.
→
4 소스 바르기재료 위에 소스를 발라요.
→
5 굽기오븐에 넣어 구워 완성해요.

순서가 바뀌거나 한 단계라도 빠지면 원하는 음식이 나오지 않아요. 알고리즘도 마찬가지로 순서와 절차가 중요해요.

🏗️ 알고리즘은 왜 필요할까? (33~34쪽)

프로그래밍 언어로 실제 코드(code)를 작성하기 전에 반드시 알고리즘을 먼저 작성해야 해요. 알고리즘 작성은 소프트웨어 개발 단계 중 가장 중요한 과정이라고 할 수 있어요.

🏢 아파트 도면 비유 · 아파트를 지으려면 먼저 도면을 설계해야 해요. 도면을 잘못 설계하면 공사 중에 문제가 생기거나, 완공된 뒤에 구조적 결함이 발견되고, 심하면 무너질 수도 있어요. 알고리즘을 잘못 작성하면 프로그램 결과에 논리적 오류가 생겨 원하는 기능을 발휘할 수 없고, 개발 과정을 처음부터 다시 해야 할 수도 있어요.

소프트웨어 개발 절차는 「기획 → 설계 → 구현 → 테스트 → 유지 보수」 순서예요. 알고리즘 작성은 그중 설계 단계에 해당해요.

✅ 알고리즘의 조건 5가지 (34쪽 표Ⅰ-3)

컴퓨터는 스스로 생각하거나 판단하지 못해요. 그래서 알고리즘은 명확하고 구체적으로 작성해야 하고, 다음 조건을 만족해야 해요.

조건뜻
입력외부에서 입력되는 데이터의 값은 0개 이상이다. 즉 입력값이 없을 수도 있다.
출력적어도 1개 이상의 결과를 출력해야 한다.
명확성절차와 표현이 명확하고 구체적이어야 한다.
수행 가능성각 절차와 표현이 논리적으로 수행 가능해야 한다.
유한성유한한 시간 내에 동작하고 결국 종료되어야 한다(무한 반복 같은 무한 동작 금지).

노래방 점수 알고리즘과 비교해 봐요 (그림Ⅰ-13).

🎵 알고리즘 1 · 동전을 넣어 노래 입력 동전, 노래 번호 / 출력 해당 노래의 반주 명확성 노래 번호마다 반주가 1:1로 연결돼 어떤 입력이 어떤 출력을 낳는지 분명해요. 가능성: 각 단계가 논리적으로 수행돼 반주를 출력 · 유한성: 노래가 끝나면 종료
🎤 알고리즘 2 · 노래하면 점수 입력 노래하는 목소리 / 출력 노래 점수 명확성 점수를 구하는 기준과 공식이 분명해요. 가능성: 각 단계가 논리적으로 수행돼 점수를 출력 · 유한성: 노래가 끝나면 종료

🧪 이건 알고리즘일까? · 5조건 판정

아래 절차가 알고리즘의 5조건을 만족하는지 골라 봐요. 「끝나는가(유한성)」, 「결과가 나오는가(출력)」, 「분명한가(명확성·수행 가능성)」를 살펴봐요.

02

알고리즘 표현

교과서 36~37쪽 · 표현 방법과 순서도 기호

쉽게 말하면같은 알고리즘도 적는 방법은 여러 가지예요. 말로 풀어 쓰는 자연어, 코드처럼 간결한 의사 코드, 약속된 기호로 흐름을 그리는 순서도—그중 순서도가 가장 널리 쓰여요.

🗣️ 알고리즘 표현 방법 (36쪽 표Ⅰ-4)

알고리즘을 표현하는 방법에는 다음과 같은 것들이 있어요.

자연어사람들이 일상에서 쓰는 말로 표현해요.예 · 「남은 시간이 충분(50분 이상)하면 버스를, 그렇지 않으면 택시를 탄다.」
의사 코드(pseudocode)자연어를 프로그래밍 언어와 유사한 형식으로 간결하게 표현해요.예 · if (남은 시간 ＞= 50분) 버스로 이동 else 택시로 이동
순서도(flowchart)약속된 기호들과 흐름선으로 표현해요.국제 표준화 기구(ISO)에서 지정한 기호와 규칙을 사용 · 아래 체험에서 직접 봐요
프로그래밍 언어Python, C 같은 실제 언어로 표현해요.알고리즘을 그대로 코드로 옮기는 단계예요.

이 중 순서도는 전체 흐름을 한눈에 파악할 수 있고 간단히 작성할 수 있는 장점이 있어 가장 많이 사용해요.

🔁 같은 알고리즘, 세 가지 표현 · 「점수 → 합격/불합격」 (37쪽 그림Ⅰ-14)

점수(score)가 60점 이상이면 「합격」, 아니면 「불합격」으로 판정하는 같은 알고리즘을 세 가지 방법으로 나란히 봐요. 버튼을 눌러 비교해요.

🔷 순서도 기호 (37쪽 표Ⅰ-5)

순서도는 국제 표준화 기구(ISO)에서 지정한 기호와 작성 규칙에 따라 그려요. 카드를 눌러 기호 ↔ 뜻을 맞춰 봐요.

📏 순서도 작성 규칙 (37쪽)

  • 순서도 표준 기호를 사용해요.
  • 처리 과정은 해당하는 기호로 표시하고, 각 기호는 흐름선(화살표)으로 연결해요.
  • 흐름선은 위에서 아래로, 왼쪽에서 오른쪽으로 그려요. 다만 「예 또는 아니요」 분기에 따라 아래에서 위로 향하는 경우도 있는데, 이는 반복문일 때 사용해요.
  • 흐름선으로 기호를 연결할 때는 흐름선끼리 교차하지 않도록 해요.
  • 처리 과정이 길어 한 면에 작성하기 어려우면 연결자를 사용해 분리해 작성해요.

💡 NS 차트 (36쪽 「정보」) 흐름을 나타내는 화살표 없이 처리를 직사각형으로 포개어 나열하는 방식이에요. 전체 논리 구조를 한 쪽에 나타낼 수 있어 제어 구조가 복합된 처리를 명확하게 식별하는 데 적합해요. NS 차트는 순서도로 변환해 나타내는 것도 가능해요.

핵심 문장 · 마무리 퀴즈 · 생각 정리 질문폼

알고리즘은 특정한 문제를 합리적으로 해결하기 위한 논리적인 절차 또는 방법이다. 코드를 작성하기 전에 반드시 먼저 작성하는 설계 단계로, 잘못 작성하면 프로그램에 논리적 오류가 생긴다.
알고리즘은 다섯 가지 조건을 만족해야 한다. 입력(0개 이상)·출력(1개 이상)·명확성·수행 가능성·유한성(유한한 시간에 반드시 종료).
알고리즘은 자연어·의사 코드·순서도(와 프로그래밍 언어)로 표현한다. 순서도는 표준 기호(터미널·처리·조건·입출력·준비·흐름선·연결자)로 전체 흐름을 한눈에 보여 주어 가장 많이 쓰인다.
