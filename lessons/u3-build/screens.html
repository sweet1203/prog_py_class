02

모듈 구현

교과서 213~215쪽 · menu.py · student.py · gui.py · main.py

쉽게 말하면급식 프로그램은 역할을 나눠 네 개의 모듈(.py 파일)로 만들어요. 메뉴를 관리하는 menu.py, 선택을 처리하는 student.py, 화면을 그리는 gui.py, 전체를 실행하는 main.py예요.

📦 menu.py · 메뉴 관리 (214쪽, 읽기용)

MenuItem은 메뉴 이름 하나를 저장하고, Menu는 여러 메뉴를 리스트로 관리해요. choose( )는 리스트를 돌며 이름이 같은 메뉴를 찾아 반환해요.

# menu.py — 메뉴 항목과 메뉴 목록을 관리
class MenuItem:              # 하나의 메뉴(이름)를 저장
    def __init__(self, name):
        self.name = name

class Menu:                  # 여러 메뉴를 관리
    def __init__(self, items):
        self.items = items         # 메뉴 리스트 초기화
    def choose(self, name):
        for item in self.items:     # 리스트를 순회
            if item.name == name:     # 이름이 일치하면
                return item          # 그 메뉴 항목을 반환
        return None                  # 없으면 None 반환

🙋 student.py · 선택 처리 (213쪽, 읽기용)

__init__( )는 생성자로, 객체가 만들어질 때 자동 호출돼 self(그 객체 자신)에 값을 저장해요. order( )는 choose( )로 메뉴가 있는지 확인해 결과 문장을 돌려줘요.

# student.py — 학생이 메뉴를 선택
from menu import Menu

class Student:
    def __init__(self, menu):      # 생성자: self(객체 자신)에 menu 저장
        self.menu = menu
    def order(self, menu_name):
        menu_item = self.menu.choose(menu_name)   # 메뉴에 있는지 확인
        if menu_item:                            # 있으면
            result = f'선택한 메뉴: {menu_item.name}입니다.'
        else:                                   # 없으면
            result = '해당 메뉴는 없습니다!'
        return result

🖼️ gui.py · 화면 그리기 (214쪽, 읽기용 · 웹 실행 X)

tkinter로 창·라벨·버튼을 만들어요. 메뉴마다 버튼을 만들고, lambda로 클릭한 버튼의 이름을 show_order( )에 전달해요. config는 라벨의 글(text)을 바꿔 결과를 보여 줘요.

# gui.py — 화면(GUI)을 그리고 버튼 클릭을 처리 · 웹에서는 실행하지 않아요
import tkinter as tk
from student import Student

class Gui:
    def __init__(self, root, student):
        self.student = student
        root.title('학교 급식 메뉴 선택')     # 창 제목
        root.geometry('280x260')           # 창 크기
        tk.Label(root, text='메뉴를 선택하세요:').pack(pady=10)
        for item in student.menu.items:
            tk.Button(root, text=item.name,
                      command=lambda name=item.name: self.show_order(name),
                      width=20).pack(pady=7)     # 메뉴마다 버튼 생성
        self.result_label = tk.Label(root, text='')
        self.result_label.pack(pady=20)
    def show_order(self, menu_name):
        result = self.student.order(menu_name)   # 선택 결과 확인
        self.result_label.config(text=result)    # 라벨에 결과 표시

📄 main.py · 전체 실행 (215쪽, 읽기용 · 웹 실행 X)

메뉴 4개로 객체를 만들고, 화면을 띄운 뒤 mainloop( )로 버튼 클릭을 기다려요. 프로그램을 시작할 때는 이 main.py를 실행해요.

# main.py — 프로그램을 시작하는 파일 · 웹에서는 실행하지 않아요
from menu import MenuItem, Menu
from student import Student
from gui import Gui
import tkinter as tk

if __name__ == '__main__':
    items = [
        MenuItem('제육볶음'),
        MenuItem('돈가스'),
        MenuItem('돼지고기 김치찌개'),
        MenuItem('비빔밥'),
    ]
    menu = Menu(items)          # menu 객체 생성
    student = Student(menu)     # student 객체 생성
    root = tk.Tk()              # GUI 기본 창 생성
    Gui(root, student)
    root.mainloop()             # 창을 띄우고 클릭을 기다림(계속 실행)

▶ 직접 해 보기 · 선택 로직 콘솔 버전 (213~214쪽 로직)

화면(tkinter) 부분을 뺀 menu + student 로직만 콘솔 버전으로 합쳤어요. 입력값 칸에 메뉴 이름을 넣고 실행하면, choose( )와 order( )가 어떻게 동작하는지 볼 수 있어요. 라면처럼 없는 메뉴도 넣어 봐요.

버튼 클릭 대신 input( )으로 메뉴 이름을 받았을 뿐, 메뉴를 찾고 결과를 만드는 핵심 로직은 gui.py가 쓰는 것과 똑같아요.

쉽게 말하면테스트는 만든 프로그램이 요구 사항대로 잘 도는지 확인하는 과정이에요. 작은 부품(모듈) 하나하나부터, 부품을 이어 붙인 모습, 그리고 완성품 전체까지 단계별로 점검해요.

테스트는 조립식 구조물을 만드는 과정과 닮았어요.

🔩 단위 테스트부품 하나가 튼튼하고 정확히 맞물리는지
→
🧱 통합 테스트부품을 이어(지붕 조립) 잘 연결되는지

🗂️ 어느 단계의 테스트일까? (216~219쪽)

아래 점검 내용을 보고, 단위·통합·시스템 중 알맞은 단계로 보내 봐요.

🧪 단위 테스트 코드 · unittest (217쪽, 읽기용 · 웹 실행 X)

파이썬 표준 라이브러리 unittest로 테스트 케이스를 코드로 적어요. assertEqual·assertIsNone 같은 함수로 예상값과 결과가 같은지 확인해요.

# test_unit_menu.py — menu.py를 단위 테스트 · 웹에서는 실행하지 않아요
import unittest
from menu import MenuItem, Menu

class TestMenu(unittest.TestCase):
    def setUp(self):                 # 테스트마다 먼저 준비되는 부분
        self.items = [MenuItem('제육볶음'), MenuItem('돈가스')]
        self.menu = Menu(self.items)
    def test_menu_item_creation(self):
        item = MenuItem('비빔밥')
        self.assertEqual(item.name, '비빔밥')      # TC-01
    def test_choose_existing_item(self):
        item = self.menu.choose('돈가스')
        self.assertEqual(item.name, '돈가스')      # TC-03
    def test_choose_non_existing_item(self):
        self.assertIsNone(self.menu.choose('라면'))  # TC-04

if __name__ == '__main__':
    unittest.main()

실행은 터미널에서 python -m unittest test_unit_menu.py 처럼 해요. 아래 실행 칸에서 같은 확인을 assert로 직접 해 볼 수 있어요.

▶ 직접 해 보기 · assert로 단위 테스트처럼 (217쪽 로직)

같은 로직에 assert를 붙여 봤어요. 조건이 참이면 통과(PASS) 메시지가 찍히고, 거짓이면 그 줄에서 오류가 나요. 실행해서 모두 통과하는지 봐요. 맨 아래 값을 틀리게 바꿔 보면 테스트가 어떻게 실패하는지도 알 수 있어요.

04

유지 보수 · 기능 바꿔 보기

교과서 216·220쪽 · 유지 보수, 예방적 유지 보수, 메뉴 추가 체험

쉽게 말하면유지 보수는 프로그램을 사용자에게 넘긴 뒤에도 고치고 다듬으며 오래 관리하는 일이에요. 새 메뉴를 더하거나 오류를 바로잡는 것도 모두 유지 보수예요.

🔧 유지 보수란? (216쪽)

유지 보수는 소프트웨어 생명 주기에서 가장 긴 기간을 차지해요. 꾸준한 유지 보수로 프로그램의 수명 연장·사용성 향상·비용 절감을 이룰 수 있어요.

💡 예방적 유지 보수 (216쪽) 지금 당장 문제가 없어도, 앞으로 생길 수 있는 문제를 미리 막고 코드의 가독성과 유지 보수성을 높이려고 하는 작업이에요.

➕ 메뉴를 더하면 결과가 바뀌어요 (220쪽 해 보기 아이디어)

교과서 해 보기는 급식 메뉴에 채식 옵션을 더해 보는 활동이에요. 아래 콘솔 버전에는 items.append(MenuItem('채식 비빔밥')) 한 줄로 새 메뉴를 넣어 뒀어요. 실행해서 채식 비빔밥이 이제 있는 메뉴가 되는지 확인해 봐요. 그 줄을 지우고 다시 실행하면 어떻게 달라질까요?

이렇게 코드를 조금 고쳐 기능을 바꾸거나 더하는 것이 유지 보수의 한 장면이에요. 이건 정답이 아니라 체험이에요 — 화면(GUI)까지 갖춘 완성은 스스로 해결하기에서 구상해 봐요.

스스로 해결하기 · 동아리 신청 프로그램

교과서 215·220쪽 · 해 보기 「동아리 신청 GUI 구현」·「개선점 보완」

쉽게 말하면급식 메뉴 프로그램의 구조를 본떠, 동아리 신청 프로그램의 구현을 구상해 봐요. 메뉴 대신 동아리 목록을 버튼으로 보여 주고, 고른 동아리를 확인해 주는 화면을 머릿속으로 설계해요.

구현은 설계 명세서를 코드로 옮겨 모듈을 작성하는 단계다. 프로그래밍 기법에는 절차적·구조적·객체지향이 있고, 급식 프로그램은 클래스·객체를 쓰는 객체지향 방식이다. 코드는 클린 코드로 간결·명확하게 쓴다.
테스트는 단계별로 한다. 단위(모듈 하나) → 통합(모듈을 이어서) → 시스템(완성품 전체) 순서로 넓혀 가며, 파이썬에서는 unittest와 assert로 예상값과 결과가 같은지 확인한다.
유지 보수는 프로그램을 넘긴 뒤 고치고 다듬으며 오래 관리하는 활동으로, 생명 주기에서 가장 길다. 예방적 유지 보수는 생길 수 있는 문제를 미리 막고 코드를 개선한다.
