01

프로그래밍의 기본 절차

교과서 25~27쪽 · 프로그래밍 과정, 소프트웨어 개발 절차

쉽게 말하면프로그램도 집을 짓듯 순서가 있어요. 무턱대고 코딩부터 하지 않고, 「무엇을 만들지(기획) → 어떻게 만들지(설계) → 실제로 만들기(구현) → 잘 되는지 확인(테스트) → 내놓고 고쳐 가기(배포·유지 보수)」의 단계를 차근차근 밟아요.

⚙️ 요구 사항 분석 이후, 프로그래밍 과정의 절차 (25쪽 그림Ⅰ-8)

요구 사항을 충분히 분석한 뒤에는, 다음 순서로 실제 프로그램을 구현해요. 알고리즘을 설계하고, 선택한 언어로 코드를 작성(코딩)하고, 소스 코드를 컴파일해 실행 파일로 바꾸고, 테스트를 거쳐 완성해요.

알고리즘 설계→코딩→컴파일→테스트→완성
🔧 문법 오류 (디버깅)컴파일 단계에서 나는 오류는 대체로 문법 오류예요. 코딩 단계로 돌아가 고쳐요.
🧠 논리 오류 (디버깅)테스트에서 결괏값이 잘못 나오는 것은 논리 오류예요. 알고리즘 설계 단계에서부터 고쳐요.

모든 오류가 수정되어 프로그램이 완성되면 알파 테스트와 베타 테스트를 거쳐요. 두 테스트를 모두 통과하면 프로그램이 일반 대중에게 배포돼요.

🏗️ 소프트웨어 개발 절차 · 5단계 (26~27쪽)

프로그램보다 더 넓은 소프트웨어를 개발할 때는 아래 다섯 단계를 거쳐요. 버튼을 눌러 각 단계가 하는 일을 하나씩 밝혀 봐요. 집을 짓는 과정에 빗대면 더 쉽게 이해돼요.

문서화 · 각 단계에서는 문서화 작업이 함께 이루어져야 해요. 문서는 함께 개발하는 모둠원과의 소통을 돕고, 나중에 유지 보수 단계에서 문제의 원인을 빠르게 찾는 데도 큰 도움이 돼요.

🃏 용어 카드 뒤집기

카드를 눌러 낱말의 뜻을 확인해요. 뜻을 먼저 떠올려 본 뒤 뒤집으면 더 잘 외워져요.

💡 왜 체계적인 절차가 필요할까? (27쪽) 소프트웨어의 규모가 커지고 복잡해지면서 여러 명의 프로그래머가 협업하는 경우가 대부분이에요. 체계적인 개발 절차는 전체 프로세스를 이해해 프로젝트를 효율적으로 관리하게 하고, 시행착오를 줄여 개발 기간과 비용을 아끼며, 배포 이후의 문제에도 빠르게 대처하도록 도와요.

02

소프트웨어 개발 방법

교과서 28~29쪽 · 폭포수 방법과 애자일 방법

쉽게 말하면같은 집도 짓는 방식이 여러 가지이듯, 소프트웨어도 개발하는 방법이 여러 가지예요. 대표적으로 처음 계획대로 끝까지 밀고 가는 폭포수 방법과, 작게 만들어 피드백을 받아 고쳐 가며 반복하는 애자일 방법이 있어요.

🤝 왜 개발 방법이 필요할까? (28쪽)

디지털 시대에 프로그램 수요가 급증하면서, 소프트웨어를 더 빨리 배포하고 새로운 요구 사항에 신속하게 대응해야 하는 상황이 생겼어요. 프로그램의 규모가 커지고 변화 속도가 빨라지면서, 여러 프로그래머가 효율적으로 협업하고 프로젝트를 체계적으로 개발·관리할 필요가 커졌어요. 그래서 대표적인 개발 방법으로 폭포수 방법과 애자일 방법이 등장했어요.

효율적인 유지 보수

체계적인 개발이 가져다주는 네 가지 좋은 점이에요.

🌊 폭포수 방법 vs 🔁 애자일 방법 (28~29쪽 그림Ⅰ-10·11)

두 방법은 개발 단계를 어떻게 진행하는가가 달라요. 버튼을 눌러 비교해 봐요.

💡 어떤 방법을 고를까? (29쪽) 개발하고자 하는 프로그램의 목표와 특성을 고려하여 적절한 방법을 선택하는 것이 중요해요. 폭포수 방법은 범위와 요구 사항이 명확한 대규모 프로젝트에, 애자일 방법은 요구 사항이 자주 바뀌는 프로젝트에 더 잘 어울려요.

04

마무리

핵심 문장 · 마무리 퀴즈 · 생각 정리 질문폼

소프트웨어 개발 절차는 기획(요구 사항 분석) → 설계 → 구현 → 테스트 → 배포 및 유지 보수의 다섯 단계를 거친다. 요구 사항 분석 뒤 프로그래밍 과정은 알고리즘 설계 → 코딩 → 컴파일 → 테스트 → 완성으로 이어지고, 문법 오류는 코딩 단계로, 논리 오류는 알고리즘 설계 단계로 돌아가 디버깅한다. 완성된 프로그램은 알파·베타 테스트를 거쳐 배포된다.
폭포수 방법은 기획·설계·구현·테스트·배포 및 유지 보수 단계를 순차적으로 진행하는 전통적인 방법이다. 범위와 요구 사항이 명확한 대규모 프로젝트에 적합하고 진행 상황을 제어해 품질을 보장하지만, 초기 계획에 의존적이라 변화에 대응하기 어렵고 개발이 느릴 수 있다.
애자일 방법은 프로그램을 작은 단위로 개발하고, 우선순위가 높은 영역부터 만들어 고객의 피드백을 반영하며 반복하는 방법이다. 변화에 유연하게 대응해 요구 사항이 자주 바뀌는 프로젝트에 적합하다. 프로그램의 목적과 특성을 고려해 적절한 방법을 고르는 것이 중요하다.
