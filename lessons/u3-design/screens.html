02

기획 · 계획 수립과 요구 분석

교과서 203~205쪽 · 계획 수립 5요소, 요구 분석 명세서

쉽게 말하면기획은 "무엇을, 왜, 어떻게 진행할지" 큰 그림을 그리는 단계예요. 먼저 계획을 세우고(계획 수립), 사용자가 진짜 원하는 것을 파악해 요구 분석 명세서로 정리해요. 이 문서가 설계와 구현의 기준이 돼요.

🗂️ 계획 수립의 5가지 요소 (203쪽)

비용·기간·자원을 고려해 계획을 세워야 원하는 결과를 얻을 수 있어요. 계획 수립에 꼭 담아야 할 다섯 가지를 카드로 확인해 봐요.

🤝 요구 분석 명세서란? (204쪽)

요구 분석은 사용자의 현재 상태와 요구 사항을 파악해, 개발에 반영할 내용을 정하는 핵심 단계예요. 이 과정이 부실하면 비용이 늘고 품질이 떨어져요. 그 최종 산출물이 요구 분석 명세서랍니다.

  • 요구 분석의 최종 산출물로, 설계·구현에서 참조할 내용을 담아요.
  • 사용자와 개발자를 연결하는 계약서 역할을 해요.

요구 분석은 아래 순서로 진행해요.

03

설계 · 모듈화와 클래스 다이어그램

교과서 206~209쪽 · 요구 분석과 설계의 차이, 모듈화, 구조 설계

쉽게 말하면설계는 "요구 분석 명세서를 어떻게 실현할까"를 구체적으로 정하는 단계예요. 전체 구조를 정하고, 큰 프로그램을 작은 모듈로 나눠요. 그리고 각 모듈(클래스)이 어떤 데이터와 기능을 갖고 서로 어떻게 연결되는지 그림으로 그려요.

🔍 요구 분석 vs 설계 (206쪽 표Ⅲ-3)

요구 분석이 무엇(What)을 만들지라면, 설계는 그것을 어떻게(How) 만들지예요.

구분요구 분석설계
산출물요구 분석 명세서설계 명세서
관점무엇(What)어떻게(How)
특징개념적·추상적사용 환경을 반영해 구체적

설계 단계는 크게 시스템 구조 설계 · 프로그램 설계 · 사용자 인터페이스(UI) 설계 세 가지로 나뉘어요.

🧩 모듈화 · 결합도는 낮게, 응집도는 높게 (207쪽)

모듈화는 소프트웨어를 작은 독립 단위(패키지·클래스)로 나누는 것이에요. 코드 재사용·유지 보수·가독성이 좋아져요. 두 카드를 눌러 모듈화의 두 원칙을 확인해 봐요.

결합도(coupling)는 모듈이 서로 의존하는 정도 → 낮을수록 좋아요. 응집도(cohesion)는 모듈 안 요소들이 관련된 정도 → 높을수록 좋아요.

알고리즘 설계와 로직 미리보기

교과서 210·211쪽 · 기본 알고리즘 STEP 1~7, GUI 레이아웃, 핵심 로직

쉽게 말하면클래스 구조를 정했으면, 이제 프로그램이 어떤 순서로 동작할지 알고리즘을 설계해요. 메뉴를 준비하고, 객체를 만들고, 화면을 띄운 뒤, 버튼 클릭을 기다렸다가, 선택한 메뉴를 확인해 결과를 보여 주는 흐름이에요.

🔢 기본 알고리즘 STEP 1~7 (210쪽)

프로그램이 실행되는 순서예요. 카드를 눌러 각 단계가 하는 일을 확인해 봐요.

🖼️ GUI 레이아웃 설계 (211쪽 그림Ⅲ-6)

사용자가 만나는 화면이에요. tkinter의 Label(글자)·Button(버튼)·pack(배치)으로 간단하고 깔끔하게 구성해요.

화면(tkinter)을 만드는 코드는 웹에서 바로 돌리기 어려워, 아래는 읽기용 코드 카드로만 봐요.

📄 gui.py 핵심 (읽기용) (210·211쪽 · 실행하지 않아요)

Gui 클래스는 메뉴마다 버튼을 만들고, 버튼을 누르면 show_order( )가 선택한 메뉴명을 확인해 결과를 라벨에 보여 줘요. 이 코드는 눈으로 읽기만 해요.

import tkinter as tk
from student import Student

class Gui:
    def __init__(self, root, student):
        self.student = student
        root.title('학교 급식 메뉴 선택')   # 창 제목
        tk.Label(root, text='메뉴를 선택하세요:').pack()
        for item in student.menu.items:   # 메뉴마다 버튼 생성
            tk.Button(root, text=item.name,
                command=lambda name=item.name: self.show_order(name)).pack()
        self.result_label = tk.Label(root, text='')
        self.result_label.pack()

    def show_order(self, menu_name):
        result = self.student.order(menu_name)   # 선택 메뉴 확인
        self.result_label.config(text=result)    # 결과를 라벨에 표시

lambda는 어떤 버튼을 눌렀는지(name)를 show_order( )에 전달하는 역할을 해요. mainloop( )는 버튼 클릭을 계속 기다리는 무한 반복이라 웹에서 멈추므로 여기선 넣지 않았어요.

▶ 핵심 로직 미리보기 · 콘솔로 돌려 보기 (menu.py·student.py 로직)

화면(tkinter)을 뺀 Menu.choose( ) 핵심 로직만 순수 파이썬으로 떼어낸 거예요. 메뉴 목록에서 이름이 같은 항목을 찾아 결과를 출력해요. 입력값 칸의 메뉴명을 바꿔 가며 ▶ 실행해 봐요.

목록에 없는 메뉴(예: 라면)를 넣으면 choose( )가 None을 돌려줘 "해당 메뉴는 없습니다!"가 나와요. 실제 프로그램에서는 이 결과를 GUI 라벨에 보여 줘요.

마무리

핵심 문장 · 마무리 퀴즈 · 생각 정리 질문폼

소프트웨어는 기획 → 설계 → 구현 → 테스트·유지 보수 순서로 개발한다. 각 단계는 산출물(요구 분석 명세서·설계 명세서·소스 코드 등)을 만들어 다음 단계로 넘긴다.
기획에서는 비용·기간·자원을 고려해 계획을 세우고, 사용자의 요구를 분석해 요구 분석 명세서를 만든다. 이 문서는 사용자와 개발자의 계약서 역할을 한다.
설계는 요구를 어떻게(How) 실현할지 정하는 단계다. 프로그램을 작은 모듈로 나누되 결합도는 낮게·응집도는 높게 유지하고, 클래스 다이어그램·패키지 구조로 표현한다.
